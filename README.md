# Ames Housing — SalePrice Prediction

## Overview

Predicts residential property sale prices in Ames, Iowa, using the Ames Housing dataset. The project covers exploratory data analysis, leak-free feature engineering, preprocessing, model comparison across five model families, hyperparameter tuning, and a single held-out test evaluation of the winning model.

## Dataset

- Source: Ames Housing dataset — 2,930 property sales, 2006–2010, roughly 80 raw features, target `SalePrice`.
- Downloaded automatically via `kagglehub` (`shashanknecrothapa/ames-housing-dataset`) into `./data/AmesHousing.csv` if not already present — see `helper_utils.py`.
- `data/`, `images/`, and `model.pkl` are gitignored. They're generated by running the notebooks, not checked into the repo.

## Workflow

### 1. Exploratory data analysis (`Ames_housing_analysis.ipynb`)

Columns are grouped into 11 domains — Zoning & Lot, Building Type & Style, Age & Depreciation, Roof & Exterior, Basement, Heating & Utilities, Living Area & Rooms, Fireplace, Garage, Outdoor & Amenities, and Sale Info. Each group gets a description table, correlation analysis (Pearson/Spearman/Kendall against `SalePrice`), box/bar/scatter plots, a missing-value summary, and a written plan for imputation, skew correction, and rare-category collapsing. These decisions are what `AmesFeatures.py` implements.

### 2. Feature engineering (`AmesFeatures.py`)

- Drops `Order`/`PID` identifiers.
- Fills "NaN means absent" categoricals (e.g. no alley, no basement) and numerics (e.g. no masonry veneer → 0 sqft) — NaN is treated as a real category, not missing data.
- Neighborhood-median imputation for `Lot Frontage`, learned on the training fold only.
- Maps ordinal quality columns (`Exter Qual`, `Bsmt Qual`, `Garage Finish`, etc.) to integers.
- Collapses rare categorical levels (e.g. rare `Sale Type` values → `"Other"`) before one-hot encoding.
- Engineers `TotalBath`, `TotalSF`, `HouseAgeAtSale`, `RemodAgeAtSale`.
- `drop_known_outliers()` removes a small number of documented Ames anomalies (>4,000 sqft homes that sold far below trend). Applied to the training split only — never to test data.

### 3. Preprocessing

- `PowerTransformer` (Yeo-Johnson) for skewed numeric columns (areas, square footage).
- `StandardScaler` for other numeric columns.
- `OneHotEncoder` for nominal categoricals.
- Target trained on `log1p(SalePrice)` via `TransformedTargetRegressor`, with predictions and metrics reported back on the original dollar scale.

### 4. Model comparison & tuning (`Ames_Housing_v.ipynb`)

Baseline `LinearRegression`, then `Lasso`, `Ridge`, `ElasticNet`, `RandomForestRegressor`, and `ExtraTreesRegressor`, each tuned with `RandomizedSearchCV` (5-fold CV). The winning model family is selected using cross-validated RMSE, not test performance — the test set is touched exactly once, for the final chosen model.

## Model

The trained pipeline — feature engineering, preprocessing, and model, as one object — is saved as `model.pkl`:

```python
import joblib
model = joblib.load("model.pkl")
predictions = model.predict(new_raw_dataframe)
```

`new_raw_dataframe` should have the same raw columns as `AmesHousing.csv` (minus `SalePrice`) — the pipeline itself handles cleaning, encoding, and scaling.

## Explainability

`Ames_Housing_v.ipynb` includes a SHAP section (a global summary plot plus a per-house waterfall plot) using `shap.Explainer`, which auto-selects an appropriate explainer for whichever model wins the comparison.

## Limitations

- Hyperparameter search uses a fixed number of `RandomizedSearchCV` iterations rather than exhaustive search.
- Tree-based feature importance can be biased toward high-cardinality categorical features.
- Reported metrics assume the notebook is run top to bottom in one pass (Restart & Run All) before committing outputs.
- ensemble models seems to overfit to the data, which might be caused due to the small dataset
